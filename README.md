# Life Atlas · 人生地图工作台

一个运行在 **Obsidian 桌面端**的中文笔记工作台，把工作、生活、学习和日常回顾放在同一个入口里。首页自动汇总由工作台管理的记录，内容保存到当前 Obsidian 仓库中的 Markdown 文件；报销单据保留原始格式。

当前版本：**1.1.0**。这是自定义插件，通过本仓库手动安装，尚未上架 Obsidian 社区插件市场。

## 插件仓库与笔记仓库有什么区别？

- **本仓库 `obsidian-life-atlas`**：保存插件源码、安装文件、测试和使用说明。
- **你的 Obsidian 笔记仓库**：保存日常笔记、项目内容、财务记录和附件。插件在这里读写数据。
- **同步工具**：Git 同步需要单独安装并配置 Obsidian Git，或者使用其他同步方式。本插件不包含 Git 登录、提交、推送或冲突合并功能。

本仓库不包含个人笔记、真实财务流水、报销单据或 GitHub 凭证。将插件上传到 GitHub，不等于上传笔记内容。

## 功能概览

| 入口 | 可以做什么 |
| --- | --- |

| 工作 · 项目中心 | 新建项目，记录目标、下一步、状态和目标日期；进入项目管理需求、方案决策、开发排障、验证交付、安排和报销单据 |
| 工作 · 排期与分工 | 将需求拆成任务，用表格管理负责人、协作人、起止日期、预计工时及状态 |
| 工作 · 业务知识 | 新增业务概念与规则、适用边界、来源依据 |
| 工作 · 工作方法 | 新增方法，记录适用场景、操作步骤和检查清单 |
| 生活 · 日常事务 | 按日期安排工作、生活、学习事项，填写时间和优先级，勾选完成 |
| 生活 · 健康与运动 | 记录运动日期、项目、时长和身体感受 |
| 生活 · 家庭与财务 | 以表格管理收支和投资流水，按月筛选、编辑及汇总 |
| 生活 · 行程规划 | 独立管理行程、起止日期、目的地、交通、住宿、预算及每日安排 |

| 日志与回顾 | 写日记、周回顾和月回顾 |

## 安装

### 环境要求

- Obsidian **桌面端**，插件声明最低版本为 `1.6.0`。
- 当前实际使用验证环境为 **macOS + Obsidian 1.15.0**；其他桌面系统和最低版本尚未实机验证。
- 暂不支持 Obsidian 移动端。
- 普通安装不需要 Node.js，不需要运行构建命令，也不依赖 Dataview 等界面插件。

### 手动安装步骤

1. 从本仓库的 [Releases](https://github.com/HuWillis/obsidian-life-atlas/releases) 下载安装包；也可以直接下载根目录的 `main.js`、`manifest.json`、`styles.css`。
2. 找到你要使用的 Obsidian 仓库文件夹，创建以下插件目录。注意目录名使用插件 ID：**`life-atlas-workbench`**。

   ```text
   你的笔记仓库/
   └── .obsidian/
       └── plugins/
           └── life-atlas-workbench/
               ├── main.js
               ├── manifest.json
               └── styles.css
   ```

3. 将这三个文件放入上述目录，避免解压后多套一层文件夹。macOS Finder 中可用 `Command + Shift + .` 显示隐藏文件夹。
4. 重启 Obsidian，打开「设置 → 第三方插件」，启用第三方插件后，启用 **Life Atlas 人生地图**。
5. 启用后工作台会自动打开。之后可以点击左侧工作台图标，或在命令面板搜索「打开人生地图工作台」。

本插件仓库已公开，源码和安装包可以直接下载。个人笔记仓库独立管理，仍保持私密。

### 更新与卸载

- **更新**：先停用插件，备份原插件文件，再替换上述三个安装文件并重新启用。无需替换整个笔记仓库。
- **停用或卸载**：在 Obsidian 设置中停用插件，必要时删除 `life-atlas-workbench` 插件目录。已经保存的 Markdown 和原始单据仍在笔记仓库内，可以继续直接打开。
- `data.json` 是 Obsidian 生成的插件运行数据，目前用于天气缓存；不属于安装包。

## 从哪里开始使用？

### 每天的工作流

1. 从「总览」查看当天关注事项，使用「安排今天」添加待办。
2. 临时想法或刚学到的内容直接放入快速收件箱，不必马上决定最终分类。
3. 进入工作、生活、学习的二级首页，使用对应场景的新增按钮保存正式记录。
4. 定期整理收件箱，在「日志与回顾」记录日记、周回顾或月回顾。

第一次使用时，列表为空是正常的。插件不预填示例笔记，所需目录会在保存记录时创建。

### 新增需求文档

进入「工作 → 项目中心 → 新建项目」，保存项目后进入该项目，再选择「需求」并新增需求文档，填写背景目标、范围、验收标准和状态。方案决策、开发排障、验证交付也分别拥有对应表单。

### 项目排期与分工

进入「工作 → 项目中心 → 具体项目 → 排期与分工」，点击「新增任务」打开弹窗。

- 每行是一项任务，可关联当前项目的需求文档，填写负责人、协作人、计划开始/结束日期、预计工时（小时）、状态和备注。
- 可先录入任务，负责人、日期及工时留空；结束日期不能早于开始日期。状态可选未开始、进行中、待验证、已完成、阻塞。
- 按关联需求、负责人、状态组合筛选；点击行内「编辑」使用弹窗修改，保存后表格更新。取消或 Esc 放弃本次未保存输入。
- 保存失败会保留输入；关闭弹窗前请先保存。周期刷新不清空正在编辑的内容。
- 删除任务先进入本地回收目录，可以撤销；删除关联需求不会删除任务，表格会显示「原需求已移除」，可以重新选择需求。
- 数据保存在 `10 工作/01 项目/项目名称/排期与分工/`，每项任务一份带唯一 ID 的 Markdown，重名任务不会覆盖。
- 排期和今日行动分别维护，当前不会自动生成日历待办；不包含 Excel 导入、AI 自动拆分或多人实时协作。

### 工作报销：项目 → 月份 → 原始文件

1. 进入一个项目，点击「工作报销」。
2. 选择所属项目和月份。
3. 选择或拖入原始单据，可以一次导入多个文件。

归档路径：

```text
90 附件/工作报销/项目名称/2026-11/原始单据.pdf
```

- 保留文件名、格式和原始字节；同一项目、同一月份下的同名文件跳过，不覆盖。
- 支持存放 PDF、照片、OFD、表格等文件；实际打开和预览能力取决于 Obsidian 及系统支持。
- `.md` 和 `.markdown` 文件会被跳过，报销入口用于原始单据归档。
- 可以移除单据并立即撤销；移除的文件先进入本地回收目录。
- 当前不提供 OCR、发票验真、金额识别、审批或自动提交报销。

### 记账和投资

「生活 → 家庭与财务」包含两个独立标签页：

- **日常收支**：记录收入和支出，按月统计收入、支出、结余，可按收支类型筛选。结余不代表账户余额。
- **投资记录**：记录买入、卖出、分红、手续费、份额和账户；汇总当月资金进出。投资流水不自动重复计入日常收支。

当前没有证券行情、银行连接或自动导入。投资汇总不代表持仓市值、盈亏或收益率；金额字段以人民币元为单位。

## 数据保存与目录规则

业务记录使用 Markdown，单据使用原文件；工作台创建的内容目录最多四层，文件本身不计作目录层级。

| 内容 | 典型保存位置 |
| --- | --- |
| 快速记录 | `00 收件箱/` |
| 项目及需求等子文档 | `10 工作/01 项目/项目名称/需求/` 等 |
| 业务知识、工作方法 | `10 工作/02 业务知识/`、`10 工作/03 工作方法/` |
| 日常安排、运动记录 | `20 生活/01 日常事务/`、`20 生活/02 健康与运动/` |
| 收支、投资流水 | `20 生活/03 家庭与财务/收支/`、`投资/` |
| 行程及每日安排 | `20 生活/04 兴趣与出行/行程名称/每日安排/` |
| AI 工程学习 | `30 学习/01 AI工程/专题名称/` |
| 软件工程学习 | `30 学习/02 软件工程/` |
| 阅读课程 | `30 学习/03 阅读与课程/课程名称/` |
| 日记和复盘 | `40 日志/年份/日记/`、`周月复盘/` |
| 报销单据 | `90 附件/工作报销/项目名称/月份/` |

### 直接编辑 Markdown 时的注意事项

- 工作台根据 frontmatter 中的 `atlas_kind`、`atlas_id` 等属性识别记录，并使用 `context` 关联项目、行程或课程。
- 多行正文通过 `<!-- atlas:字段名 -->` 与 `<!-- /atlas:字段名 -->` 标记识别。可以编辑标记之间的正文，请保留这些标记和记录 ID。
- 普通 Markdown 文件不会因为放入某个目录就自动进入汇总；目前没有通用的既有笔记导入功能。
- 如果文件已被外部修改，保存旧表单会报错，防止覆盖外部修改。请重新打开记录后继续编辑。
- 格式损坏或关联异常的记录会被跳过，并显示对应路径和原因；原文件仍保留。
- 修改项目、行程或课程的显示名称时，现有物理目录名保持稳定，不会自动迁移目录。
- 删除记录会移至 `.trash/life-atlas/`。当前操作可撤销；重开后可从该目录手动找回，恢复时不要覆盖同名文件。

## 隐私、天气与同步

- 笔记和附件由插件写入当前本地 Obsidian 仓库，不由插件发送到 AI 服务或第三方笔记服务。
- 天气通过 Open-Meteo 获取，默认地点固定为**合肥**，使用城市坐标，不读取设备定位，也不会随请求发送笔记正文。
- 天气在启动时获取，之后每 30 分钟刷新。无法连接时显示不可用或缓存状态；缓存超过一小时会标记为缓存天气。
- 当前没有天气城市设置界面。如需修改，需调整 `plugin.js` 中的城市名称、坐标和时区，然后重新构建。
- 界面中的「Git 自动同步」文案不表示同步已经配置或推送成功。同步状态应以 Obsidian Git / GitHub Desktop 为准。
- 如果笔记仓库配置了 Git 同步，记录和附件是否上传取决于该仓库的跟踪与忽略规则。大量或较大的单据会增加仓库体积。
- 私密 GitHub 仓库限制访问权限，但不是笔记端到端加密。本插件自身也不对本地文件进行加密。

## 当前边界

- 主要面向个人使用；没有多人实时协作、云端账户或移动端支持。
- 不包含 AI 对话、模型 API 接入或自动生成笔记。AI 工程是学习内容分类。
- 目录分类和界面目前由代码定义，没有通用设置面板。
- 文件变化会触发刷新，并有每分钟定时刷新；当前会扫描仓库，超大笔记库的性能尚未专项验证。
- 工作台采用浅色视觉样式，未提供完整的主题适配配置。

## 开发与验证

开发需要 Node.js `>=20.19.0` 及 pnpm 9。`linkedom` 只用于开发测试，插件运行不依赖它。

```bash
git clone https://github.com/HuWillis/obsidian-life-atlas.git
cd obsidian-life-atlas
pnpm install --frozen-lockfile
pnpm build
pnpm test
```

也可以直接执行：

```bash
node build.js
node --test tests/*.test.js
```

构建会将模块合并为独立 `main.js`，避免 Obsidian 的模块加载方式导致相对引用失败。修改源文件后必须重新构建；修改 `styles.css` 不需要重建 JavaScript。

| 文件 | 职责 |
| --- | --- |
| `plugin.js` | Obsidian 插件生命周期、工作台视图、天气 |
| `schedule.js` | 排期表格及任务弹窗 |
| `ui.js`、`shell.js`、`styles.css` | 工作台交互、结构和样式 |
| `schema.js` | 各类记录的字段定义 |
| `store.js` | 校验、序列化、目录规则、记录与单据管理 |
| `io.js` | Obsidian 文件读写适配 |
| `build.js` | 生成可安装的 `main.js` |
| `tests/` | 存储、交互与打包测试 |

现有 27 项自动测试覆盖真实临时文件读写、外部编辑冲突、目录与日期校验、单据保真和同名跳过、撤销删除、工作/生活/学习入口、汇总及打包加载。交互测试使用模拟 DOM，不等同于 Obsidian 实机视觉测试。测试数据只写入临时目录，不需要个人笔记仓库。

## 常见问题

**启用后没有看到工作台？**

先确认三个安装文件位于 `.obsidian/plugins/life-atlas-workbench/` 下。重启 Obsidian 后，使用命令面板搜索「打开人生地图工作台」。

**已有笔记为什么没有自动出现在首页？**

首页汇总工作台格式的记录；普通笔记不包含所需的识别属性和正文字段标记。可以从相应栏目新建，再将正文整理进去。

**停用插件后还能使用笔记吗？**

可以。Markdown 和原始附件仍保留，只是工作台的表单、汇总和导航入口停止运行。

**日期图标与文字挤在一起怎么办？**

使用本仓库最新的 `styles.css`，并重新启用插件。当前版本已为日期、月份输入框分开预留文字与右侧图标空间。

**可以直接公开发布或二次分发吗？**

当前仓库用于个人维护，尚未指定开源许可证；上传 GitHub 不自动意味着授予开源使用或分发许可。
